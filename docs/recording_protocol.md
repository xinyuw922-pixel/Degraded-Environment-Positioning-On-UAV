# 采集、评测和归档协议

版本：record-v0.1。模板不是可执行采集器；本文件描述待实现的数据契约。

## 1. 标识和目录

例：`20261116T180000+0800_ROOM01_RIG01_B03_T02_ACCEPT_R01`。
时间使用Asia/Shanghai并显式带时区，机器关联保留Unix时间。日期示例不是实际run。

```text
/home/nuc1/positioning_data/
  calibration/<calib_id>/
  maps/<map_id>/
  batches/<batch_id>/batch_plan.yaml
  runs/<run_id>/
    manifest.yaml
    run_record.md
    raw/                  # 原始bag、ULog；完整保留
    snapshots/            # 参数、标定、软件版本、topic类型/频率、TF
    reference/            # 人工测量与停靠时间表
    events.csv
  analyses/<analysis_id>/
    analysis_manifest.yaml # parent_run_id、输入hash、代码/配置、对齐方式
    trajectories/          # 导出轨迹，不覆盖原始数据
    metrics.json
    figures/
    report.md
  registry/run_registry.csv
```

每个ID只能创建一次。重跑评测新建analysis_id，禁止覆盖旧结论。复制模板时在真实run目录填写，不往templates写实测数据。

## 2. 原始数据清单

以运行时探测到的topic为准，保存明确topic白名单及类型。不默认`rosbag -a`，不默认所有topic存在。

| 来源 | 必须保留的候选数据 | 说明 |
|---|---|---|
| 通用 | /tf、/tf_static、/rosout、设备/算法诊断 | 保存启动后取得的静态TF，采集开始晚也须确认bag内存在 |
| Odin1 | /odin1/imu、/odin1/odometry、/odin1/odometry_highfreq、/odin1/cloud_raw | 保留原生位姿；高频topic按实际确认 |
| Odin1图像 | /odin1/image/compressed | 需要时记录；图像与位姿时序另查 |
| MID-360 | /livox/lidar、/livox/imu | 必须保留逐点offset_time；CustomMsg/PointCloud2不能混淆 |
| D435i | 左右灰度Image及各CameraInfo、RGB Image及CameraInfo、IMU数据 | 按实际命名；gyro/accel或合并IMU均记录来源和插值策略 |
| 算法 | 原始odom、path、地图校正、质量、reset、更新统计 | 原始odom与闭环后轨迹独立命名，不让算法争用同一TF |
| PX4 | 桥接前后里程计、状态、ULog及参数 | 尚未实现，不能把ROS输入流当作飞控已融合 |

D435i优先保存原始像素；如选择无损压缩记录须保存解码方式。为节省存储省略某一路流时显式登记，不能事后宣称做过该输入消融。

不同ROS工作区切换会改变包解析；保存实际执行文件路径、来源commit与启动参数。不得依靠未记录的.bashrc叠加环境复现实验。

## 3. 单次运行流程

### 采集前

1. 创建新run目录，登记batch内预定试验，填写manifest的plan部分。
2. 核查设备/rig/calib/map/protocol ID、冻结配置和模型；分配实际算法frame与topic，避免重复TF权威。
3. 保存必要软件和硬件信息、启动命令及配置快照/hash；不保存完整环境变量或凭据。
4. 验证参考测量、时间戳、当前时钟域、逐点时间、相机模式和同步设置。
5. 根据60 s试采的真实落盘速率估计全批数据量，预留容量；记录CPU/内存/磁盘、USB/以太网争用。
6. 记录协议版本和初始位置；明确初始化区间。设备预热以温度/状态稳定为依据并记录实际等待，不虚构统一预热秒数。

### 采集中

1. 先录原始数据和状态，再执行路线，保留初始化和运行后的静止段。
2. 实时记录停靠开始/结束时间、物理参考ID、动作、遮挡、灯光、失跟和reset。
3. 记录缺失和异常；不可中途改配置而不切新run。中止也保留原始文件和原因。
4. 同时运行多算法时检查资源争用；主比较优先使用同bag离线配对，实时链路单独测量。

### 采集后

1. 正常结束采集，等待bag/ULog完整落盘。终止未正常关闭的文件登记corrupt/incomplete，不覆盖原件“修好”。
2. 检查实际topic、消息数、时间范围、频率/最大间隔、时间倒退、TF和图像解码。
3. 生成SHA-256清单并记录字节数；原始数据只读归档。文件修复或裁剪是新派生产物。
4. 补充run_record、事件和登记表。运行状态与结果字段分开：完成采集不等于验收通过。
5. 新建analysis目录，冻结输入、代码、配置、参考、地图和对齐文件，才执行评测。

## 4. 指标定义

所有位置转换到rig_base后再比较；长度m、时间s、角度报告deg并保留内部rad约定。

- **静止抖动**：初始化后固定180 s，`||p(t)-mean(p)||`的P95及XYZ标准差，另报告姿态波动。不是绝对准确度。
- **静止分段漂移**：末10 s位置均值减首10 s位置均值的模长。发生reset时保留事件，不跨reset伪装为连续漂移。
- **参考停靠点误差**：每次10 s停靠取末5 s位置均值，与独立测得的参考坐标比较；在每run内对有效停靠点计算三维RMSE、P95、最大值和XYZ误差。
- **位移误差**：两个实测参考位置之间的估计位移向量，与参考位移比较；可用于无地图的B01/B03，但不能由此推断固定房间坐标已恢复。
- **闭合误差**：末段与起始静止段均值的位置/姿态差，分别报odom与map结果；起终物理停靠误差须列出。
- **重复定位**：固定房间坐标变换下，多次独立启动返回同一参考点的分布。无地图里程计的全局重定位为N/A。
- **连续ATE/RPE**：仅在连续独立真值可用且时间配准明确时计算。记录采样、对齐、间隔、遗漏区间；本阶段默认N/A。
- **接收/处理/桥接延迟**：分别报告P50/P95/max。跨时钟相减须先验证同步；报告源stamp语义、时差不确定度，不能把host接收时间叫曝光时间。
- **位姿覆盖率/最长中断**：以冻结周期分箱计算，记录stale阈值及分母。失跟、重置、协方差异常和时间跳变单独统计。
- **视觉作用**：B05的图像启用/禁用配对消融，记录实际视觉更新数量、跟踪数和被拒绝原因，不只看染色点云。
- **飞行控制误差**：有飞行目标和独立参考时另算，不与定位误差混为一个指标。

稀疏参考点权重按冻结协议统一；记录参考轴向不确定度，不把它从误差中随意减去。
主指标只用独立标定点得到的固定刚体对齐。每run最佳SE(3)或Sim(3)结果只能作为清楚标注的辅助诊断。

## 5. 汇总与失败处理

- 筛查每条件3次；正式批次独立每条件5次。先列出n_planned、n_attempted、n_valid、n_failed、n_aborted、n_missing。
- 每run先汇总指标，再给所有run的中位数/范围；不按帧数让长run支配所有结论。
- 每run内部P95与跨runP95含义不同，必须标明；只有5次重复时不声称尾部风险已经可靠估计。
- 失败类型：设备未连接、初始化失败、数据不完整、时间不明、失跟、重定位错误、算法崩溃、操作中止、参考测量不足。
- 无效区间和剔除原因写events.csv；不能静默裁掉失跟区间或反复重跑只挑最好结果。
- 禁止用点面残差、重投影误差或静止抖动替代最终定位误差。
- 所有缺失指标填写null并提供reason，不填0；未完成试验不写pass。
